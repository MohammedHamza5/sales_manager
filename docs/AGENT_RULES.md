## 2. القرارات المعمارية المقفولة نهائيًا 🔒

| # | البند | القرار المقفول | المبرر والحدود الصارمة |
|---|---|---|---|
| 1 | **المنصة والتشغيل** | Windows Desktop (Offline بالكامل) | لا اتصال بالإنترنت، لا مزامنة سحابية في V1، لا Backend خارجي. |
| 2 | **State Management** | **Cubit** (`flutter_bloc`) فقط | ممنوع Bloc/Events إلا لآلة حالات بالغة التعقيد، ممنوع Riverpod أو Provider. |
| 3 | **قاعدة البيانات** | **Drift** فوق `sqlite3` عبر `NativeDatabase` | دعم أصيل للـDesktop، استعلامات Type-safe، Streams للـDashboard، وTransactions ذرية. |
| 4 | **المبالغ المالية (Money)** | **`int` بالقرش (1 ج.م = 100 قرش)** | **ممنوع `double` منعًا باتًا لأي مبلغ مالي.** الحسابات جمع/طرح أعداد صحيحة مطلقة الدقة. التحويل إلى جنيه يتم في طبقة العرض فقط. |
| 5 | **الكميات (Quantities)** | **`Decimal` (package: `decimal`)** | ممنوع `double` للكميات. الوحدات المختلفة (كيلو/جرام/لتر/قطعة) تتطلب دقة كسرية. تُخزن كـ TEXT في SQLite عبر TypeConverter. |
| 6 | **سياسة البيع والمخزون** | **المنع الصارم والمطلق للبيع بالسالب** | **حظر تام لتجاوز المخزون المتاح.** إذا كانت الكمية المطلوبة > الرصيد الحالي يرفض النظام حفظ الفاتورة فوراً. |
| 7 | **المصروفات (Expenses)** | **مُدرجة رسمياً في V1** | إدارة المصروفات وبنودها وخروج نقدية من الخزينة تلقائياً ضمن نطاق النسخة الأولى. |
| 8 | **الطباعة والفواتير** | **طابعة حرارية (80mm) + طباعة عادية (A4)** | توفير قالبي طباعة (إيصال كاشير حراري + فاتورة ضريبية/تجارية A4 قياسية). |
| 9 | **المستخدمون والصلاحيات** | **مستخدم واحد V1 مع قابلية التوسع** | لا شاشة دخول في V1، ولكن الجداول تحمل حقل `created_by` افتراضي للتوسع المستقبلي. |
| 10 | **طريقة الإدخال** | **إدخال يدوي وبحث سريع بالاسم والكود** | التركيز على سلاسة الإدخال اليدوي والاختصارات السريعة. |
| 11 | **الذرية (Atomicity)** | **Single `db.transaction()` per UseCase** | كل عملية متعددة الجداول (بيع/شراء/تحصيل/دفع/مرتجع/تسوية) تُنفذ داخل Transaction واحدة. فشل خطوة = Rollback كامل. |
| 12 | **سجل التتبع (Audit Log)** | **تلقائي داخل نفس الـTransaction** | لا تعديل بيانات دون تسجيل audit_log فورًا داخل نفس الـTransaction. |
| 13 | **حظر الحذف النهائي** | **No Hard Deletes / No In-place Mutation** | الكيانات (منتجات/عملاء/موردين) تُعطّل (`is_active = false`). العمليات السابقة لا تُحذف ولا تُعدل؛ الإلغاء يتم بإنشاء عملية عكس (Reversal). |
| 14 | **اللغة والاتجاه** | **العربية فقط (RTL)** | لا بنية ARB معقدة في V1. جميع النصوص مركزية في `core/strings/app_strings.dart`. |
| 15 | **فصل الـDomain** | **Dart نقي 100%** | ممنوع استيراد `package:flutter` أو `package:drift` داخل مجلد `domain/`. |
| 16 | **تجربة المستخدم (UI/UX)** | **عصب النظام وأولوية قصوى** | المعاينة الفورية للأثر المالي والمخزني (Zero-Surprise)، دعم كامل للوحة المفاتيح (Enter/Esc/Autofocus)، خلو تام من الـOverflow، وتخطيط مريح لسطح المكتب. |

## 3. القرارات المؤكدة من العميل (محسومة رسميًا)
- **البيع بالسالب:** محظور حظرًا تامًا ومطلقًا.
- **المصروفات:** مبنية ومُدرجة في النسخة الأولى.
- **الطباعة:** دعم الطباعة الحرارية (80mm) والطباعة القياسية (A4).
- **المستخدمون:** مستخدم واحد مع تجهيز البنية للتوسع لمستخدمين متعددين لاحقًا.
- **الإدخال:** إدخال يدوي واختياري للباركود دون اشتراط أجهزة خاصة.
- **النسخ الاحتياطي:** نسخ تلقائي محلي + خيار تصدير واستعادة يدوي عبر USB.

## 4. دورة التنفيذ الإلزامية لكل مهمة (The Strict Execution Loop)

لكل مهمة من مهام خارطة الطريق (`P0-01` إلى `P13-04`):

```text
1. اقرأ الملفات ذات الصلة أولاً بدقة.
2. اعرض خطة موجزة ومحددة (≤ 7 أسطر).
3. انتظر موافقة المستخدم الصريحة.
4. نفّذ التغيير دفعة واحدة وبأعلى دقة، دون حشو أو Refactor جانبي.
5. شغّل التوليد إذا تطلب الأمر: `dart run build_runner build --delete-conflicting-outputs`.
6. تحقّق بالتشغيل الفعلي: `flutter analyze` + `flutter test` (0 أخطاء، 0 تحذيرات).
7. حدّث سجل المهام وحالة التنفيذ.
```

> ⛔ **تحذير:** ممنوع قول "تم" أو "اكتملت المهمة" دون تشغيل `flutter analyze` والتأكد من خلو المشروع تمامًا من أي أخطاء أو تحذيرات Linting.

## 5. تعريف الجاهزية (Definition of Done - DoD)

لا تُعتبر أي ميزة أو شاشة جاهزة ومقبولة إلا بتحقيق كافة الشروط التالية:
1. **Clean Architecture:** فصل صارم (`domain/`, `data/`, `presentation/`).
2. **الذرية:** أي حفظ متعدد الأطراف يتم داخل `db.transaction()` عبر UseCase مخصص.
3. **Audit Log:** تسجيل الحدث تلقائيًا في `audit_log` داخل نفس الـTransaction.
4. **حالات الواجهة الأربعة الإلزامية:**
   - حالة التحميل (Loading Skeleton / Indicator).
   - حالة الفراغ (Empty State برسالة واضحة وإجراء مقترح).
   - حالة الخطأ (Error View مع رسالة عربية مفهومة وزر إعادة المحاولة).
   - حالة النجاح والبيانات (Success View).
5. **سلامة الموارد:** فحص `context.mounted` بعد أي `await`، واستدعاء `dispose()` لكل `TextEditingController` و`StreamSubscription` و`FocusNode`.
6. **الدقة المالية والمخزنية:** لا `double` للأموال (استخدام `int` قرش)، ولا `double` للكميات (استخدام `Decimal`).
7. **الجودة والتحليل:** نجاح `flutter analyze` بدون أي `error` أو `warning` أو `info` مهمل.
8. **الاختبارات:** وجود اختبارات وحدة للـUseCases الحسابية واختبارات تكامل للـTransactions في الذاكرة `NativeDatabase.memory()`.
