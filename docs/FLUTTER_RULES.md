## 1. إدارة الحالة (State Management with Cubit)

- **Cubit حصريًا:** كل شاشة أو ميزة تمتلك `Cubit` مخصصًا و`State` مغلقًا (`sealed class`).
- نمط الحالات الإلزامي في كل Cubit يعرض بيانات:
  ```dart
  sealed class FeatureState extends Equatable {
    const FeatureState();
  }

  class FeatureInitial extends FeatureState {
    const FeatureInitial();
    @override
    List<Object?> get props => [];
  }

  class FeatureLoading extends FeatureState {
    const FeatureLoading();
    @override
    List<Object?> get props => [];
  }

  class FeatureEmpty extends FeatureState {
    final String message;
    const FeatureEmpty({required this.message});
    @override
    List<Object?> get props => [message];
  }

  class FeatureError extends FeatureState {
    final String message;
    const FeatureError({required this.message});
    @override
    List<Object?> get props => [message];
  }

  class FeatureLoaded extends FeatureState {
    final List<Item> items;
    // بيانات إضافية
    const FeatureLoaded({required this.items});
    @override
    List<Object?> get props => [items];
  }
  ```

## 2. الحالات الأربع الإلزامية في كل شاشة (The 4 Mandatory UI States)

كل شاشة تجلب أو تعرض بيانات يجب أن تتضمن صراحة:
1. **حالة التحميل (Loading):** استخدام مكونات skeleton أو مؤشر تحميل مريح مع بقاء الهيكل ثابتًا دون اهتزاز الواجهة.
2. **حالة الفراغ (Empty State):** أيقونة معبرة + رسالة واضحة (مثال: "لا توجد منتجات مسجلة حتى الآن") + زر إجراء مباشر (مثل: "إضافة منتج جديد").
3. **حالة الخطأ (Error State):** عرض رسالة خطأ عربية ودية دون إظهار تفاصيل تقنية معقدة + زر "إعادة المحاولة" (`Retry`).
4. **حالة النجاح (Success/Loaded):** عرض البيانات المكتملة مع إمكانية الفرز والبحث والترشيح.

## 3. معايير سطح المكتب (Desktop Ergonomics)

### 3.1 ملاحة لوحة المفاتيح والاختصارات (Keyboard First)
- بيئة الكاشير والمبيعات تتطلب السرعة دون الحاجة لاستخدام الماوس دائمًا:
  - `F1`: مساعدة / عرض الاختصارات.
  - `F2`: فاتورة بيع جديدة.
  - `F3`: البحث السريع عن منتج.
  - `F4`: البحث السريع عن عميل.
  - `F9`: حفظ وإتمام الفاتورة نقديًا.
  - `Escape`: إغلاق النوافذ المنبثقة أو إلغاء الإدخال الحالي.
  - `Enter`: الانتقال التلقائي بين حقول الإدخال في النماذج (Focus Traversal).
- دعم ماسح الباركود (Barcode Scanner) حيث يرسل الرمز متبوعًا بـ `Enter` للبحث والإضافة التلقائية لسلة البيع.

### 3.2 تخطيط الشاشات واستجابة النوافذ
- التطبيق موجه لشاشات سطح المكتب بدقة قياسية (1366x768 فأعلى).
- حد أدنى لحجم النافذة: `1024x700` بكسل لمنع تداخل العناصر.
- استخدام `NavigationRail` أو قائمة جانبية (`Sidebar`) ثابتة لسهولة التنقل السريع بين الوحدات.
- استخدام جداول بيانات (`DataGrid` / `DataTable`) ذات ترويسات ثابتة وخلايا محاذاة بالأرقام لليمين/اليسار طبقًا للأصول المحاسبية.

## 4. اللغة والهوية البصرية (RTL & Styling)

### 4.1 اللغة العربية والاتجاه (RTL Only)
- التطبيق بالكامل موجه من اليمين إلى اليسار (`Directionality(textDirection: TextDirection.rtl)`).
- الخط المعتمد: خط عربي واضح وسهل القراءة للأرقام والحروف (مثل Cairo أو Almarai أو الخط الافتراضي للنظام المعالج بوضوح).
- **لا hardcoded strings داخل الـ Widgets:** جميع النصوص تُستدعى من `core/strings/app_strings.dart`.

### 4.2 تنسيق الأرقام والعملات والتواريخ
- العملة تُعرض دائمًا بوضوح: `١٥٠٫٠٠ ج.م` أو `150.00 ج.م` حسب الإعداد المختار.
- الفواصل العشرية وفواصل الآلاف متسقة ومقروءة بوضوح في الجداول والمطالبات المالية.
- التواريخ تُعرض بالصيغة القياسية: `YYYY/MM/DD` مع الوقت عند الحاجة في سجلات الحركة والـ Audit.

## 5. قواعد الأداء وإدارة الموارد (Lifecycle & Memory)

1. **فحص `context.mounted`:** إلزامي بعد أي عملية غير متزامنة (`await`) قبل استخدام `BuildContext`.
2. **تحرير الموارد (Disposal):**
   - كل `TextEditingController`، و`FocusNode`، و`ScrollController` يجب تحريره داخل `dispose()`.
   - كل `StreamSubscription` يجب إلغاء اشتراكه عند إغلاق الشاشة أو إيقاف الـ Cubit.
3. **تجنب إعادة البناء غير الضرورية:**
   - استخدام `const` مع الـ Widgets الثابتة دائمًا.
   - استخدام `BlocBuilder` مع خاصية `buildWhen` لمنع إعادة رسم الشاشة إلا عند تغير الحالة المعنية بالفعل.

## 6. ميثاق هندسة وتجربة المستخدم الصارمة (Strict Desktop UI/UX Covenant) 🌟

تجربة المستخدم (UX) وسلاسة الواجهة (UI) هي عصب المشروع والعمود الفقري لنجاحه لدى مستخدم نقطة البيع:

### 6.1 المعاينة الحية الفورية ومنع المفاجآت (Zero-Surprise Live Preview)
- في أي شاشة أو نافذة تؤثر على المخزون أو المال، يجب عرض **المعاينة الفورية للأثر قبل التأكيد**:
  - مثال التسوية: إظهار (الرصيد الحالي ⬅ التغيير ⬅ الرصيد الجديد المتوقع) بألوان ديناميكية فور كتابة الرقم.
  - مثال الفاتورة: إظهار إجمالي الخصم، صافي الفاتورة، والمتبقي على العميل فور كتابة المدفوع لحظياً.
- التمييز اللوني الدلالي الموحد:
  - 🟢 **الأخضر (Success / Inflow):** الوارد، الإيداع، الزيادة في المخزون، السداد المكتمل.
  - 🔴 **الأحمر (Danger / Outflow):** الصادر، الخصم، العجز، التوالف، المصروفات، الرصيد الحرج.
  - 🟠 **البرتقالي (Warning):** اقتراب نفاد المخزون، المبالغ المعلقة، التحذيرات غير المانعة.
  - 🔵 **الأزرق / الرمادي الفاخر:** النصوص التعريفية، الترويسات، الأرقام المحايدة.

### 6.2 بيئة الإدخال الفائق للكاشير (Ultra-Fast Keyboard Ergonomics)
- **التركيز التلقائي (Auto-focus):** الحقل الأهم في أي نافذة أو شاشة يُركز عليه المؤشر تلقائياً فور الفتح بدون نقرة ماوس.
- **التنقل عبر `Enter`:** الضغط على `Enter` في أي حقل ينقل المؤشر للحقل التالي بسلاسة (`FocusScope.of(context).nextFocus()`).
- **التنفيذ التلقائي على آخر حقل:** الضغط على `Enter` في الحقل الأخير يُنفذ أمر الحفظ مباشرة إذا كان الإدخال سليماً.
- **الإلغاء بـ `Esc`:** إغلاق النوافذ المنبثقة فورياً بمفتاح الهروب دون تعليق.
- **حظر تكرار النقرات (Debounce & Double-Submission Prevention):** زر الحفظ يتعطل تلقائياً ويُظهر مؤشر تحميل مدمج أثناء معالجة العملية لمنع إرسال طلب مكرر.

### 6.3 وضوح الجداول والبيانات (Data Density & Desktop Legibility)
- الجداول مصممة لسطح المكتب: ترويسات ثابتة واضحة، محاذاة الأرقام والكميات بدقة مع تمييز العملة والوحدة.
- تأثير التحويم (`Hover state`) على صفوف الجداول لتسهيل القراءة وتتبع العين على الشاشات العريضة.
- حظر الـ Overflow تماماً: دعم التمرير ثنائي الأبعاد (رأسي وأفقي) عند انخفاض دقة العرض لضمان عرض 100% من البيانات دون أي تشوه بصري.
- بطاقات المؤشرات الرئيسية (KPI Cards) في أعلى كل شاشة لإعطاء نظرة سريعة شاملة للمدير أو الكاشير قبل التعمق في التفاصيل.
